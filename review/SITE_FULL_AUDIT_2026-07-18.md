## 결론

읽기·퀴즈·달란트 구매의 20명 동시 실행은 정상이다. 20명 모두 로그인한 뒤 `읽기 완료 → 퀴즈 정답 제출 → 상품 구매` 60건이 실패 없이 처리됐고, 원장·잔액·구매를 독립 재조회했을 때 누락과 중복이 없었다.

최초 점검에서는 비로그인 첫 화면의 **기존 회원 교회 검색이 모든 교회에 대해 결과 0개**로 재현됐다. 후속 조사에서 상시 데이터·규칙 장애가 아니라 일시 읽기 실패를 실제 0건으로 숨기는 복구 결함으로 확정했고, 자동·수동 재시도와 상태 분리를 배포해 공개 교회 검색을 다시 확인했다. 관리자 이메일 로그인도 정상이다.

## 후속 원인 확정·운영 배포 (2026-07-18)

- 후속 운영 재검사에서는 비인증 Firestore SDK와 실제 공개 화면 모두 레거시 교회 8건을 정상 반환했고 `서부제일교회` 검색 결과도 나타났다. 따라서 위 0건 현상을 데이터·규칙의 상시 장애로 단정한 표현은 정정한다.
- 확정된 결함은 `publicDirectoryMeta`와 레거시 읽기가 일시적으로 모두 실패했을 때 `getChurchDirectory()`가 오류를 빈 배열로 바꾸고, `ChurchPicker`가 이를 실제 0건으로 표시한 뒤 재시도하지 않는 구조다. 최초 실패의 하위 오류는 당시 코드가 삼켜 사후 확정할 수 없다.
- 로컬 수정은 최초 시도 포함 최대 2회 자동 재시도, 최종 오류 전달과 실패 캐시 제거, `로딩 / 읽기 오류 / 실제 결과 없음` 상태 분리, 수동 `다시 시도`를 추가했다. Firestore 규칙·공개 범위·운영 데이터는 바꾸지 않았다.
- 회귀 검사와 전체 validate(플랫폼 API 442건), build, 로컬 브라우저의 `서부제일교회` 결과 노출 및 게스트 개역개정 본문 진입을 확인했다.
- P3는 Vite chunk 분할로 메인 JS를 약 1,465.19kB(gzip 389.81kB)에서 485.80kB(gzip 151.97kB)로 줄여 500kB 경고를 제거했다. Firebase compat 구현은 유지했다.
- `platformApi`의 Node-safe 지연 경계를 브라우저 전용 `platformAuth.js`로 분리해 `firebase.js` 정적·동적 중복 import 안내도 제거했다. 최종 빌드는 경고 0건이다.
- `b4f4df9`와 후속 `a6c72c3`을 `main`에 push하고 GitHub Pages에 배포했다. 공개 메인 파일 `assets/index-Dc3p7dCd.js`는 로컬과 SHA-256 `a712838ee8a6b876a777ea107e6e6e0997436c63da159b76dfd8a6228ef28f1c`가 일치했고, HTML 참조 파일 9개와 `platformAuth-CDVLXWGr.js`가 모두 HTTP 200이었다.
- 새 공개 브라우저에서 `서부제일교회` 검색, 게스트 진입, 개역개정·새번역 본문을 확인했다. Firestore rules·Edge 함수·운영 데이터는 변경하지 않았다.

## 발견한 문제

### P1 — 일시 읽기 오류가 실제 교회 0건으로 표시됨

- 최초 점검에서는 공개 디렉토리에 교회가 있음에도 테스트·기존 운영 교회 검색이 모두 0건으로 나타났다.
- 후속 재검사에서는 현재 운영 8개 교회와 `서부제일교회` 결과가 정상이며, 메타 403 뒤 레거시 폴백도 정상임을 확인했다. 따라서 교회 데이터 또는 규칙의 상시 장애는 아니다.
- 확정 원인은 메타와 레거시 읽기가 일시적으로 모두 실패했을 때 최종 오류를 `[]`로 성공 처리하고, `ChurchPicker`가 다시 읽지 않아 해당 화면에서 영구 0건처럼 보이게 한 구조다.
- 최초 하위 오류는 당시 코드가 기록하지 않아 확정할 수 없다.
- 운영 해결: 최대 2회 자동 재시도, 최종 오류 전달·캐시 제거, 로딩/오류/실제 없음 분리, 수동 재시도, 회귀 검사 편입.
- 배포 확인: 비인증 새 공개 브라우저에서 `서부제일교회` 검색 결과와 게스트 개역개정·새번역 본문을 확인했다. 실제 통신 실패 UI는 운영 장애를 인위적으로 만들지 않고 자동 회귀 검사로 검증했다.

### P3 — 초기 번들 크기 경고

- 빌드는 성공했지만 메인 JavaScript가 약 1.47MB(압축 약 390KB)이며 Vite의 500KB 경고가 발생했다.
- `firebase.js`가 정적·동적으로 동시에 import되어 별도 chunk로 분리되지 않는 경고도 있었다.
- 기능 오류는 아니지만 저사양 휴대전화·느린 네트워크의 첫 로딩에 영향을 줄 수 있다.
- 운영 해결: vendor와 대형 데이터 chunk를 분리해 메인 JS를 485.80kB(gzip 151.97kB)로 줄였고, 브라우저 전용 `platformAuth.js` 지연 경계로 정적·동적 중복 import 안내까지 제거했다. 최종 빌드 경고는 0건이다.
