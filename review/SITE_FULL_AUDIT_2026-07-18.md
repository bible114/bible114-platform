## 결론

읽기·퀴즈·달란트 구매의 20명 동시 실행은 정상이다. 20명 모두 로그인한 뒤 `읽기 완료 → 퀴즈 정답 제출 → 상품 구매` 60건이 실패 없이 처리됐고, 원장·잔액·구매를 독립 재조회했을 때 누락과 중복이 없었다.

다만 비로그인 첫 화면의 **기존 회원 교회 검색이 모든 교회에 대해 결과 0개**로 재현됐다. 이 때문에 이름·생년월일 방식 기존 회원은 교회를 선택할 수 없어 로그인 단계로 진입하지 못한다. 관리자 이메일 로그인은 정상이다.

## 발견한 문제

### P1 — 기존 회원 교회 검색 결과가 항상 비어 있음

- 공개 `settings/churchDirectory`에는 9개 교회가 있고, 테스트 교회와 기존 운영 교회가 포함되어 있음을 관리자 REST 읽기로 확인했다.
- 브라우저에서 테스트 교회 이름과 기존 운영 교회 이름을 각각 검색했으나 결과 버튼이 0개였다.
- 새 탭·전체 새로고침 후에도 동일했다.
- `publicDirectoryMeta/current` 문서는 현재 없으며, 비인증 REST 읽기는 403을 반환한다. 앱은 이 경우 레거시 `settings/churchDirectory`로 되돌아가도록 작성돼 있지만 실제 화면에는 목록이 채워지지 않았다. 정확한 실패 지점은 추가 계측이 필요하다.
- 영향: 이름·생년월일 방식 기존 회원 로그인이 막힌다. 회원가입·추가 공동체 선택 등 `ChurchPicker`를 재사용하는 화면도 같은 영향을 받을 가능성이 높다.

권장 다음 조치:

1. `getChurchDirectory()`에 공개 메타 읽기 실패·레거시 폴백 성공/실패 상태를 구분하는 진단을 추가한다.
2. `publicDirectoryMeta/current`가 없는 운영 상태를 자동 테스트 fixture로 고정한다.
3. 로그인 화면에서 레거시 목록 1건 이상이 실제 결과 버튼으로 나타나는 브라우저 회귀 테스트를 추가한다.
4. 수정 배포 후 비인증 새 브라우저에서 운영 교회와 신규 교회를 각각 검색한다.

### P3 — 초기 번들 크기 경고

- 빌드는 성공했지만 메인 JavaScript가 약 1.47MB(압축 약 390KB)이며 Vite의 500KB 경고가 발생했다.
- `firebase.js`가 정적·동적으로 동시에 import되어 별도 chunk로 분리되지 않는 경고도 있다.
- 기능 오류는 아니지만 저사양 휴대전화·느린 네트워크의 첫 로딩에 영향을 줄 수 있다.
