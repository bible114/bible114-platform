## 배포 순서안 — 실행 금지, 별도 승인 필요

계획서의 순서대로 데이터 이관 → Firestore rules → functions → hosting. 현재 자료에서 데이터 이관/본문 수정의 안전한 적용 대상과 완료 상태가 확정되지 않았고, rules safety 게이트도 실행되지 않았으므로 실제 배포 단계로 진행하면 안 됩니다. 특히 계획상 금지된 실DB 쓰기·배포는 승인 전 수행하지 않습니다.

## 되돌리기

1. 배포 전에 현재 승인된 배포 버전과 각 단계의 대상/변경 목록을 기록하고, 기존 rules·functions·hosting 산출물 및 필요한 데이터 복구본을 확보합니다.
2. 장애가 나면 마지막으로 적용한 구성요소만 직전 정상 버전으로 되돌립니다. hosting은 이전 정상 빌드로 복귀하고, functions와 rules는 각각 직전 배포 버전/규칙으로 복원합니다.
3. 데이터 변경은 코드 롤백만으로 복구되지 않으므로, 별도 검증된 역방향 절차와 복구본 없이는 실행하지 않습니다.
4. 복구 후 승인된 읽기 전용 점검과 전체 검증을 수행하고, 결과를 기록합니다. 이 문서는 실제 복구 명령/백업 존재를 확인한 기록이 아니므로, 배포 전에 운영 담당자가 해당 절차와 복구본을 구체적으로 확인해야 합니다.
